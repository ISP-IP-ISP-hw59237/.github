<h2>服务器是壳，地址是核</h2>
<p>美国 ISP 住宅服务器，报价里包含两块：一台运行环境，以及一条（或多条）住宅出口。两块的成本性质完全不同。运行环境的成本透明、可比较；出口的成本取决于稀缺度与独享程度，差异极大。</p>
<p>所以看报价时，先拆开看这两块，再判断总价是否合理。笼统比总价，容易得出错误结论。</p>

<h2>配置里最容易被低估的两项</h2>
<p>第一项，内存。多环境并行时，内存是最先触顶的资源。配置不足的表现是卡顿、环境启动失败、程序被系统杀掉。</p>
<p>第二项，磁盘类型。机械盘在随机读写上明显慢，表现为系统卡顿、程序启动慢、日志写入阻塞。容量可以小一点，类型不要将就。</p>

<h3>CPU 为什么常常过剩</h3>
<p>因为账号操作类任务的计算强度很低。买高配 CPU 往往换不来体感提升，钱花错了方向。真正需要算力的是视频处理、批量自动化这类任务。</p>
<h3>上行为什么要单独确认</h3>
<p>标称带宽多为下行。上传、推流依赖上行，上行不足时下行再大也用不上。这一项必须单独问，并要求写入服务说明。</p>

<h2>价格的三块构成</h2>
<p>第一块，计算资源。价格透明，容易比较。第二块，住宅出口。取决于独享程度与地区稀缺度，是价格的主要变量。第三块，服务。含配置、监控、支持，各家的边界不同。</p>
<p>第三块最不透明。「包运维」与「只交付」差别很大，报价可能相同但内容完全不同。要看清单。</p>

<h2>选购时的五个问题</h2>
<p>一，出口是否独享，几条。二，上行带宽多少。三，是否有流量上限，超出如何计。四，能否自行重装系统或更换镜像。五，故障响应时限多少。</p>
<p>五个问题里，第四个影响后续部署的灵活度。不支持自定义系统的，很多工具装不上，方案会受限。</p>

<h2>落地清单</h2>
<p>采购前：算清能同时跑几个环境、每个环境需要多少内存、峰值上行多少。三项写清，配置就好定了。</p>
<p>采购后：验证出口归属、测上行与下行、连续运行看稳定性、确认能自助重启与重装。</p>
<p>两张单子都不长，但能把「买回来才发现不合适」的概率压到很低。</p>

<h2>先定瓶颈，再定配置</h2>
<p>买服务器最常见的浪费，是把预算堆在了不构成瓶颈的部件上。多环境并行时，瓶颈几乎总是内存，而不是 CPU；素材上传时，瓶颈在上行带宽，而不是核数。先想清楚自己最常做的操作是什么，再把这台机器的主要预算放在对应部件上，剩下的够用即可。</p>
<p>判断方法很朴素：跑一遍典型工作日，看资源占用曲线。哪个先到顶，哪个就是该加钱的地方。凭配置表推测，往往猜错方向。</p>
<p>服务器报价通常含三项：硬件规格、带宽、地址数量。三项里最容易缩水的是带宽的共享属性，以及地址是否整段连续。要求对方在合同里写明可用地址范围与带宽属性，是这类采购里最划算的一次确认。</p>
<h2>常见问答</h2>
<h3>配置越高越好吗</h3>
<p>不是。超过需求就是浪费，而且高价配置未必解决真正的瓶颈。先找瓶颈再配参数。</p>
<h3>能只要出口不要服务器吗</h3>
<p>多数可以，纯代理端口方案就是这种。成本更低，适合已有设备的团队。</p>
<h3>带宽含在价格里吗</h3>
<p>不一定。有的含固定带宽，有的按流量另计。签约前确认口径与超出处理方式。</p>
<h3>需要备份吗</h3>
<p>建议要。环境配置、浏览器配置、脚本都值得备份。快照服务费用不高，价值很高。</p>
